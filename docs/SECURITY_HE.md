# אבטחה ופרטיות ב-SUPER CODER CLOUD

מסמך זה מסביר בשפה פשוטה איך המערכת מגינה על המידע של העסקים ושל הלקוחות שלהם, מה מגיע אוטומטית מהתשתית, ומה נשאר באחריות בעל המערכת.

## מה מגיע אוטומטית מהתשתית (Vercel + Supabase)

| נושא | מצב |
| --- | --- |
| הצפנה בתעבורה (HTTPS / TLS 1.2+) | אוטומטי לכל דומיין, כולל דומיינים של אתרי לקוחות. התעודות מתחדשות לבד |
| הגנה מפני DDoS ורשת הפצה (CDN) | מובנה ב-Vercel Edge Network |
| הצפנת מסד הנתונים "במנוחה" (AES-256) | מובנה ב-Supabase, כולל גיבויים |
| גיבויים יומיים | Supabase (בתוכנית Pro יש גם שחזור לנקודת זמן - PITR) |
| בידוד שרתים ועדכוני אבטחה למערכת ההפעלה | באחריות הספקים |

## מה המערכת עצמה עושה

- **הפרדה מלאה בין עסקים (multi-tenant):** כל טבלה מוגנת ב-Row Level Security במסד הנתונים עצמו. גם אם יש באג בקוד, עסק אחד לא יכול לקרוא מידע של עסק אחר.
- **הרשאות לפי תפקיד:** בעלים, מנהל, מכירות, תמיכה, שיווק, אנליסט, צפייה בלבד. כל פעולה נבדקת גם בשרת וגם במסד הנתונים.
- **סודות מוצפנים:** טוקנים של WhatsApp, Telegram, PayPal, Morning, iCount, פיקסלים של Meta/TikTok ו-Google Analytics, יומנים ומיילים נשמרים מוצפנים ב-AES-256-GCM עם מפתח (`ENCRYPTION_KEY`) שנמצא רק ב-Vercel. אף משתמש, כולל בעל העסק, לא יכול לקרוא אותם בחזרה.
- **מידע אישי שנשלח לפלטפורמות פרסום** (Meta, TikTok, Google) נשלח רק מגובב (SHA-256), ורק עבור לקוחות שהסכימו לדיוור, אלא אם העסק כיבה את זה במפורש.
- **הגבלת קצב (rate limiting)** על טפסים ציבוריים, הזמנות, צ'אט, מעקב באתרים, פעולות AI ותשלומים.
- **ולידציה כפולה:** כל קלט נבדק ב-Zod בשרת ושוב באילוצים של מסד הנתונים.
- **Webhooks חתומים:** כל webhook נכנס (PayPal, NOWPayments, WhatsApp, Telegram, Twilio) נבדק לפי חתימה. Webhooks יוצאים נחתמים ב-HMAC-SHA256.
- **קישורי פעולה חתומים** (אישור פגישה, "בוצע" במשימה) עם תוקף. פתיחת הקישור רק מציגה אישור, והפעולה עצמה מתבצעת בלחיצה, כך שתצוגה מקדימה ב-WhatsApp או סורק מיילים לא יפעילו אותה.
- **Web Push:** ההודעות מוצפנות מקצה לקצה (RFC 8291) ונשלחות רק לשירותי Push רשמיים של הדפדפנים. זה מונע שימוש בשרת כדי לפנות לכתובות שרירותיות (SSRF).
- **יומן ביקורת (Audit log)** לפעולות רגישות: הרשאות, חיובים, חיבורים ושינויים של מנהל הפלטפורמה.
- **מעקב באתרים (wave 17):** מזהה מבקר אקראי, בלי כתובת IP ובלי טביעת אצבע. המערכת מכבדת "Do Not Track", ובמצב GDPR המעקב מתחיל רק אחרי הסכמה לעוגיות. אירועים נמחקים אחרי 180 יום.
- **ניהול הסכמה בכל הערוצים:** "הסר" / STOP בכל ערוץ עוצר את כל ההודעות האוטומטיות והקמפיינים לאותו לקוח.

## מה באחריותך כבעל המערכת

1. **לסובב (להחליף) כל סוד שנחשף אי פעם**, כולל סודות שהודבקו בצ'אט, במייל או בקובץ. כרגע יש להחליף:
   - PayPal Client Secret
   - את ה-Vercel Token הישן
   - את סיסמת מסד הנתונים (Supabase → Settings → Database → Reset password)
   - את ה-GitHub Personal Access Token הישן
2. לא לשמור סודות בקבצים בריפו. שמרו אותם רק ב-Vercel → Settings → Environment Variables.
3. להפעיל אימות דו-שלבי (2FA) ב-Vercel, Supabase, GitHub, PayPal ובחשבון המייל.
4. לשמור את `ENCRYPTION_KEY` במקום בטוח (מנהל סיסמאות). בלי המפתח הזה אי אפשר לפענח את החיבורים השמורים.
5. לתת לכל עובד את התפקיד המינימלי שהוא צריך.

## תקנים ואישורים (ISO 27001 / SOC 2)

אלה לא תכונה שאפשר "להוסיף בקוד". אלה אישורים שמקבלים אחרי ביקורת חיצונית של גוף מוסמך, והם בודקים גם נהלים ארגוניים: ניהול גישה, טיפול באירועים, הדרכות והמשכיות עסקית. המערכת בנויה כך שתעבור ביקורת כזו בקלות יחסית: RLS, הצפנה, יומן ביקורת, הפרדת סביבות ותיעוד. בנוסף, Vercel ו-Supabase עצמן מחזיקות SOC 2 Type II, ואפשר לבקש מהן את הדוחות.

## פרטיות (חוק הגנת הפרטיות / GDPR)

- דפי המדיניות באתרים נוצרים אוטומטית לפי פרטי העסק. אם יש מבקרים מאירופה, סמנו "מבקרים מהאיחוד האירופי (GDPR)" בפרטי העסק של האתר.
- לקוח יכול לבקש עיון, תיקון או מחיקה. מחיקת איש קשר מוחקת גם את השיחות, ההודעות והמסמכים שקשורים אליו.
- ייצוא נתונים (CSV) זמין לבעלי הרשאה בלבד.

## דיווח על בעיית אבטחה

אם מצאתם בעיה, אל תפרסמו אותה. שלחו מייל לכתובת התמיכה שמופיעה ב-`BILLING_BUSINESS_EMAIL`, ונחזור אליכם תוך 72 שעות.
